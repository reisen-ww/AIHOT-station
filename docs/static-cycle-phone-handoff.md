# 手机安装与切换交接

本文件是尚未执行的切换说明。当前授权只完成本地实现和验证；没有把新入口安装到手机，没有改真实计划或发布。双 TTS 仍按用户“先不启动”决定保持原现场。

## 安装前需要核实

先通过已批准的本地传输识别当前设备和运行用户，再只读确认容器入口、Node.js 24、Git、字体/图像依赖、四站源码目录、公开联系图片目录和可用工作盘。历史记录中的设备序列号、PID、路径和端口只是核对线索，不能直接当当前事实使用。旧远程入口已退役，新操作也不调用会停 TTS 的旧刷新入口。

历史设备型号、序列号、系统用户、物理路径和端口已从公开归档中省略。迁移前必须重新识别目标设备并核对实际容器入口、源码路径、Node.js、Git、依赖和兼容性；不能复用历史连接信息或路径判断当前状态。

`static-repair/rolling-20261109/phone-file-inventory-v1.json` 核对了本任务 483 个变更路径和 4 份受保护的 `site/models.ts`，不是手机整棵源码盘点。其中 251 项与本地 Git HEAD 基线相同、227 项为手机没有的新增路径、5 项手机源码有差异，4 份 models 与本地相同。5 份差异原件及 SHA 已保存到 `phone-baseline-files-v1/`：四站 StationSwitch 仍使用端口/Pages 两种切站方式；AIHOT 的旧路由配置依赖 `/tmp/batch-paths.json`，新配置由三阶段构建替代。未来安装必须逐路径核对当时的手机摘要，未知漂移应停止；不得整站覆盖或覆盖 models。4 份 feedback 路由只登记待移除计划，本次没有在手机删除。

用户已决定不公开运营者和联系方式，四站条款/隐私源页已去除身份联系字段和待填提示；不再将这两项作为安装前待填写资料。本轮已确认最近1000篇并集原评分≥85历史公开文章，四站合计硬上限900MB，700–900MB可接受、700/800不提前阻断。未来操作者仍需核实四份只读数据库连接由哪些环境变量提供、Git 作者身份和现有认证方式。Git 作者不等于法律页面的运营者。不能把本地隔离数据库连接复制到手机，不能为了运行读取或同步其他业务密钥。

## 可审阅的安装顺序

1. 保全手机当前源码、相关启动脚本和真实 cron spool 的内容与摘要，记录回退路径。只读核实所有旧的手动、开机与计划入口；它们必须在同一切换窗口统一退役，不能与新入口并行写同一输出。
2. 从四个已核验的真源仓库交付源码差异和未跟踪新增文件，不从历史脚本、审计快照或旧部署包整站覆盖。保留各站 site、industry、modules、资源及运行配置的差异。传输前后逐文件比较摘要，安装依赖另按实际差异处理。
3. 在四站源码根之外建立全新的独立工作目录，把 static-cycle.config.example.json 填成实际配置；四站所有手动、计划和重试入口共用它。配置只记录数据库环境变量名，不写连接凭据。新入口只保全第一次遇到的旧 client，不能把原业务目录指定成工作目录。
4. 先运行不带 --publish 的完整生成，核每站 manifest/static-release、总 static-site-release、实际字节、全部历史报告和公开地址。检查失败目录与锁状态；本地 PC 的成功不能替代手机依赖和文件系统验证。
5. 双 TTS 已另获准恢复并保持健康后，再验证冷缓存和热缓存整轮生成。必须覆盖完整周期与两小时目标；只验启动、单站耗时或窄屏截图不算。生成入口不启停 TTS，也不为腾空间或内存调用旧 release-mem/memguard。
6. 明确获准真实提交、推送和使用现有认证后，使用 --publish-only --publish 处理已完整生成的候选。确认固定仓库 reisen-ww/hot-pages、main 和 /hot-pages 基址；保留正常历史，不强推、不 orphan、不空提交。远端完整确认成功后，再在获准窗口替换旧计划。
7. 用 static-cycle.cron.example 填写真实的启动器、配置、环境和日志路径。每小时触发配合 --scheduled 的两小时时槽，失败重试仍使用同一锁和 pending。安装后回读真实 spool 和调用链的字节，观察整轮结果；模板存在不算计划已生效。

## 回退和异常

任何步骤失败，保留旧版、原始数据库/备份、失败 run、未确认 transport 和日志。回退优先恢复先前确认的完整版本及原计划记录，不能拼接四站不同 revision，也不能通过删除 pending 或强推解决远端分支冲突。

若进程被硬杀或手机重启留下 cycle.lock，先核清本轮所有相关子进程均已结束。锁目录没有 owner、PID 已退出或记录时间很旧都不是自动清理依据；只有获准操作者确认归属后，才保留并移走准确锁路径。不要按进程名批量终止，也不要自动抢锁。

真实上线反馈、手机负载表现和长期周期仍需独立证据。安装执行人应把配置版本、源码摘要、实际命令和运行记录追加到任务 PROGRESS，不能只回报“安装成功”。
