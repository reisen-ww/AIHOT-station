## 三条贯穿全部文档的原则

**1. 先怀疑信号，再怀疑系统。**
健康检查全站超时的真实原因是 `Invoke-RestMethod` 的连接池被拖垮；"模型一次都没成功"是因为查了不存在的 `status='ok'`。工具和查询本身会坏。

**2. 局部数据不下趋势结论。**
40 分钟 4 个点看着像崩溃，拉全天 59 次探测才发现成功率 91.5%、从未连续两次失败。判断恶化要用全天样本 + 连续失败次数。

**3. 区分"配置意图"和"运行实际"。**
改了 `.env` 不等于生效，进程不重启就还在跑旧配置。核实以运行痕迹（回执里的模型名、接口返回值）为准，不以文件内容为准。
